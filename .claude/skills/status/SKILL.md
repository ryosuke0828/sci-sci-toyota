# STATUS.md の更新

`STATUS.md` は**今井泰介先生にそのまま送れる状態を常に保つ**ための文書である。

## 手順

1. `STATUS.md` を読む。
2. 前回更新以降の差分を `log.md` の最新エントリ、および `data/derived/` の出力から確認する。
3. 下記のルールに従って `STATUS.md` を書き換える。
4. 冒頭の「最終更新」を今日の日付にする。
5. 変更点を1〜3行でユーザーに報告する。

## 書き方のルール

**この文書に書くもの**

- 目的（変わらない。書き換えるのは今井先生の指示が変わったときだけ）
- 計画のフェーズと、その状態（未着手 / 実行待ち / 進行中 / 完了）
- 完了したフェーズの**結果の数字**（件数・率・サンプルサイズ）
- ブロッカー（内容・影響・対応の3点セット。対応が「要判断」なら §5 に判断事項として書く）
- 今井先生に判断してもらう必要がある事項と、こちらの推奨
- 次の作業（3項目まで）

**この文書に書かないもの**

- 作業の経緯、試行錯誤、失敗とその修正の過程（これらは `log.md` に書く）
- 技術的な実装の詳細（API のクエリ構文、スクリプトの内部設計など）
- スクリプト名・ノートブック名（詳細レポートへのリンクだけ書く）
- 「〜と思われる」「〜の可能性がある」といった曖昧な記述。確認できた事実か、未確認かを明示する
- 謝辞、前置き、感想

**分量**: A4で2ページ以内に収める。フェーズが完了して記述が増えたら、古いフェーズの記述を数字だけに圧縮する。

**詳細の逃がし方**: 検証や分析の詳細は `docs/reports/` にレポートを作り、STATUS.md からはファイルパスで参照するだけにする。

## 状態の判定基準

| 状態 | 条件 |
|---|---|
| 完了 | 出力データが `data/derived/` に保存され、再実行で再現できる |
| 進行中 | 着手済みだが出力が未保存、または一部のみ |
| 実行待ち | 実装は完了しており、外部要因（クォータ・承認待ち等）だけが残っている |
| 未着手 | 上記以外 |

「実行待ち」は必ずブロッカー表にも対応する行を持つ。

## 更新後にやること

`STATUS.md` を更新したら、**`scripts/backup_repo.sh` を実行して Drive 外へバックアップする**。
2026-08-06 に Google Drive がフォルダごと過去の状態に巻き戻り、成果物を失った事故があったため。

## 関連ファイル

- `log.md` — 作業の詳細ログ（経緯・試行錯誤を含む。STATUS.md とは役割が違う）
- `docs/reports/` — 個別の検証・分析レポート
- `AGENTS.md` — 恒久的な運用ルール
